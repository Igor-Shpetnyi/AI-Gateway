## Що таке Graphify і навіщо він потрібен

Graphify — open-source skill (MIT license, `github.com/safishamsi/graphify`), який перетворює проєкт (код, доки, PDF, схеми БД, діаграми, навіть відео) на **queryable knowledge graph**. Замість того щоб AI-асистент читав файли по одному й тримав їх у контекстному вікні, він робить точковий запит до графа й отримує тільки релевантний підграф.

**Технічна база:**
- Tree-sitter — AST-парсинг 36+ мов, **повністю локально, без LLM-виклику на код**
- LLM (Claude/GPT/Gemini/Ollama) — семантична екстракція з доків, PDF, зображень
- NetworkX — граф-структура
- Leiden algorithm — кластеризація на семантичні спільноти без ембедінгів і векторної бази

**Вихідні артефакти:**
```
graphify-out/
├── graph.html       # інтерактивна візуалізація
├── graph.json       # queryable граф — джерело правди для запитів
├── GRAPH_REPORT.md  # god nodes, несподівані зв'язки, suggested questions
└── cache/           # інкрементальний кеш для --update
```

## Як це економить токени: механіка

Ключова ідея — **графовий запит замість повного прочитання файлів**.

| Без Graphify | З Graphify |
|---|---|
| Асистент грепає/читає 10-50 файлів, щоб зрозуміти "як влаштована авторизація" | `graphify query "what connects auth to database?"` повертає скопований підграф |
| Кожен новий запит — заново перечитує контекст | Граф persist в `graph.json`, повторний запит не тягне попередній контекст |
| На великому репо контекстне вікно забивається сирими файлами | BFS-підграф по темі ~1.5-2k токенів замість ~100k+ naive |

Заявлений бенчмарк на змішаному корпусі (3 GPT-репо + 5 attention-статей + діаграми, ~92k слів): середня вартість запиту ~1.7k токенів проти ~123k naive — **71.5× зменшення**.

**Механізм примусу:** після `graphify claude install` встановлюється **PreToolUse hook**, який перехоплює виклики Read/Glob/Bash-grep асистента і підказує йому спочатку звернутись до графа. Це не порада в CLAUDE.md, яку можна проігнорувати — це активний хук на рівні інструментів.

**Що НЕ економить токени:**
- Сама побудова графа для не-коду (доки, PDF, зображення) — це LLM-виклики, вони коштують токенів одноразово при екстракції
- AST-частина коду — безкоштовна завжди, локальний Tree-sitter

## Встановлення

```bash
# Рекомендовано — ізольоване середовище
uv tool install graphifyy

# Альтернативи
pipx install graphifyy
pip install graphifyy   # можлива проблема з PATH, дивись Troubleshooting нижче
```

> Офіційний пакет — `graphifyy` (подвійне "y"). CLI-команда — `graphify` (без другого "y"). Інші пакети `graphify*` на PyPI не афілійовані з автором.

Реєстрація skill для асистента (глобально, для всіх проєктів):

```bash
graphify install                    # Claude Code (за замовчуванням)
graphify install --platform cursor  # або інший з ~25 підтримуваних агентів
```

## Розгортання на новому проєкті

Логіка тут інша, ніж для існуючого репо: сенс не "побудувати граф зараз" (нема з чого), а **поставити автоматизацію так, щоб граф ріс разом з кодом безкоштовно**.

### Крок 1 — одразу після `git init`

```bash
git init
# ... перший каркас (package.json / pyproject.toml / структура папок) ...

graphify install --project    # project-scoped skill, комітиться в репо
graphify hook install         # git hook: AST-перебудова графа на кожен коміт, без LLM
graphify claude install       # CLAUDE.md + PreToolUse hook
```

`hook install` — головний елемент цього кроку. AST-частина безкоштовна й автоматична: граф оновлюється на кожен коміт без жодної ручної дії і без витрати токенів.

### Крок 2 — `.graphifyignore` до першого білду графа

```
node_modules/
dist/
build/
*.generated.*
.env*
coverage/
```

Критично зробити це **до** першого запуску `/graphify .` — інакше god-nodes покажуть сміття (`webpack.config.js`, згенеровані файли) замість реальної архітектури.

`.gitignore` враховується автоматично; `.graphifyignore` мерджиться поверх нього і виграє при конфліктах.

### Крок 3 — перший реальний граф

Не варто ганяти `/graphify .` на 3 файлах — сенсу нуль. Запускай, коли з'явився хоч мінімальний скелет (основні модулі/сервіси/класи):

```
/graphify .
```

Далі граф підтримує себе сам через hook. Ручний `--update` потрібен тільки для не-коду:

```
/graphify ./docs --update
```

### Реалістичні очікування

Перші 1-2 тижні нового проєкту економія токенів буде мінімальна — просто нема достатньо файлів, у яких асистент "губиться". Ефект стає відчутним приблизно з **20-30+ файлів з реальною бізнес-логікою**, коли контекст одного запиту "як влаштовано X" вже не влазить у природну пам'ять асистента.

## Розгортання на існуючому проєкті

```bash
cd existing-project
graphify install --project
graphify hook install
graphify claude install

# .graphifyignore до білду!
/graphify .
```

Для великих легасі-репо (>5000 файлів) — розглянь `--mode deep` для якіснішої семантичної екстракції зв'язків, або спочатку прогони на підпапці:

```
/graphify ./src --mode deep
```

## Щоденний workflow

**Замість:**
> "Прочитай весь проєкт і поясни як працює авторизація"
(сотні тисяч токенів контексту, повільно, дорого)

**Роби:**
```bash
graphify query "what connects auth to database?"
graphify explain "AuthService"
graphify path "LoginController" "SessionStore"
```

Завдяки PreToolUse hook асистент у Claude Code/Codex/Gemini CLI **сам** віддає перевагу цим командам замість grep — тобі часто не треба нічого просити вручну, досить сформулювати задачу природньою мовою.

**При рефакторингу / великих змінах:**
```bash
graphify update ./src           # інкрементальний ре-екстракт тільки змінених файлів
graphify update ./src --force   # якщо після рефакторингу нод стало менше і граф "боїться" це прийняти
```

**Перед code review / PR:**
```bash
graphify prs               # дашборд: CI, review-статус, worktree mapping
graphify prs 42             # deep-dive по конкретному PR з graph impact
graphify prs --conflicts    # PR, що діляться графовими спільнотами — ризик merge-конфліктів
```

**Для архітектурного огляду:**
```bash
graphify export callflow-html   # Mermaid-діаграми call-flow, читабельний HTML
```

## Команди: повний довідник під задачі

| Задача | Команда |
|---|---|
| Побудувати граф з нуля | `/graphify .` |
| Оновити тільки змінені файли | `/graphify . --update` |
| Перекластеризувати без ре-екстракції | `/graphify . --cluster-only` |
| Швидкий білд без HTML (великий репо) | `/graphify . --no-viz` |
| Точковий запит | `graphify query "<питання>"` |
| Шлях між двома сутностями | `graphify path "A" "B"` |
| Пояснення конкретного вузла | `graphify explain "ClassName"` |
| Додати статтю/документ ззовні | `graphify add https://arxiv.org/abs/...` |
| Автооновлення на коміт | `graphify hook install` |
| MCP-сервер для повторних запитів агента | `python -m graphify.serve graphify-out/graph.json` |
| Спільний HTTP-сервер для команди | `python -m graphify.serve graphify-out/graph.json --transport http --api-key "$SECRET"` |

## Командна робота

`graphify-out/` призначений для коміту в git — щоб уся команда стартувала з готовою мапою.

**`.gitignore` доповнення:**
```
graphify-out/cost.json      # локальні дані по вартості LLM-викликів
# graphify-out/cache/       # опційно: комітити заради швидкості або пропускати заради розміру репо
```

**Workflow команди:**
1. Один розробник запускає `/graphify .` і комітить `graphify-out/`
2. Решта команди пуляє зміни — асистент одразу читає готовий граф
3. `graphify hook install` — після кожного коміту граф автооновлюється (AST, без витрат)
4. Git merge driver автоматично union-мержить `graph.json` при паралельних комітах — конфліктів у файлі графа не буває

**Спільний доступ через MCP HTTP:**
```bash
python -m graphify.serve graphify-out/graph.json \
  --transport http --host 0.0.0.0 --port 8080 --api-key "$SECRET"
```
Команда підключає IDE до `http://<host>:8080/mcp` — локальний `graphify` на машині кожного розробника не потрібен.

> За замовчуванням bind `127.0.0.1` (тільки loopback). Якщо відкриваєш на `0.0.0.0` — обов'язково `--api-key`, інакше граф проєкту доступний будь-кому в мережі.

## Оптимізація витрат на LLM-екстракцію

Не-код контент (доки, PDF, зображення, відео) вимагає LLM-виклику. Витрати можна контролювати:

```bash
# Локальний backend — нуль зовнішніх витрат, дані не покидають машину
graphify extract ./docs --backend ollama

# Менші чанки для дешевших/локальних моделей
graphify extract ./docs --token-budget 4000

# Обмежити паралельні виклики (корисно для локального inference)
graphify extract ./docs --max-concurrency 2
```

**Data residency:** якщо є вимоги щодо даних — `--backend ollama` (повністю локально) або явний `--backend claude`/`--backend openai` з конкретним провайдером. Backend Kimi (`MOONSHOT_API_KEY`) маршрутизує на сервери Moonshot AI в Китаї — врахуй це для чутливих проєктів.

**Код завжди безкоштовний** — Tree-sitter працює локально без API-ключа взагалі.

## Типові помилки і як їх уникнути

| Проблема | Причина | Рішення |
|---|---|---|
| `graphify: command not found` | Bin-директорія не в PATH | `uv tool update-shell` (uv) / `pipx ensurepath` (pipx), новий термінал |
| `uvx graphify ...` не резолвиться | `uv tool run` читає перше слово як ім'я пакета, а пакет — `graphifyy` | `uvx --from graphifyy graphify install` |
| God-nodes показують сміття | `.graphifyignore` не налаштований до першого білду | Налаштувати ignore-файл, тоді `graphify extract . --force` |
| Граф "втратив" вузли після рефакторингу | Захист від випадкового зменшення графа | `--force` або `GRAPHIFY_FORCE=1` |
| `graph.json` конфліктує при паралельних комітах | Merge driver не встановлений | `graphify hook install` — встановлює union-merge автоматично |
| HTML-граф не відкривається (>5000 нод) | Занадто великий для браузера | `--no-viz`, працювати через `graphify query` напряму з JSON |

## Коли Graphify не варто ставити

- **Дуже маленький проєкт** (менше ~20 файлів з логікою) — оверхед на інфраструктуру (hook, конфіги, `graphify-out/` в репо) не окупається; звичайний `CLAUDE.md` з описом архітектури дасть той самий ефект за долю зусиль
- **Одноразовий скрипт / прототип** — граф не встигне себе окупити до кінця життя проєкту
- **Команда без дисципліни комітити `graphify-out/`** — без цього кожен розробник будує граф заново, сенс командної економії токенів зникає

**Правило простого рішення:** якщо асистент регулярно перечитує одні й ті самі файли по колу, або контекст одного запиту "як влаштовано X" вже не влазить у розумні межі — це сигнал ставити Graphify. Якщо такого болю ще нема — рано.
